## Result
```
**Cause:** Go's module downloader (Go ≥1.14) marks extracted module cache files/directories read-only by design; containerd 2.3.3's build populates `.gopath/pkg/mod` inside the per-recipe WORKDIR, and a later plain `rm -rf` cleanup (Jenkins workspace cleanup) cannot delete entries inside those read-only directories.

**Affected:** containerd 2.3.3+git on imx93frdm (aarch64) and imx6 (armv7); torizon-docker and torizon-minimal image variants; likely also runc, crictl, docker-cli and other Go-module-based recipes in meta-virtualization.

**Status:** new pattern

**Fix:** Add a postfunc in the containerd recipe (or shared `go-mod.bbclass` if one exists) to restore write permissions after Go builds: 
```
do_compile[postfuncs] += "fix_gopath_mod_perms"
fix_gopath_mod_perms() { chmod -R u+w ${WORKDIR}/.gopath/pkg/mod 2>/dev/null || true; }
```
Alternatively/additionally, update the CI matrix pipeline's workspace-cleanup step from `rm -rf <dir>` to `chmod -R u+w <dir> 2>/dev/null; rm -rf <dir>` so it handles read-only module caches regardless of recipe. Long-term: point `GOMODCACHE` at a persistent cache outside per-recipe WORKDIR and clean via `go clean -modcache` rather than `rm -rf`.
```
